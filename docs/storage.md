# ScreenMark storage

- **Library:** titles live in IndexedDB (`screenmark_library`: `items`, `meta` and `thumbs` stores) and are written per changed title by a data worker. The `items` store uses its ID key for normal edits and a compound `metadataSource` / `category` / `providerId` index for direct provider-link lookups. Schema version 4 removed unused status/category/date indexes, version 5 removes the unused share/PDF cache, and version 6 adds the provider-link index. If the data worker stops or times out, queued operations are replayed in order by the main-thread fallback after its change-detection cache is reloaded. `localStorage` (`splitapp_screenmark_v1`) keeps only a small startup mirror of preferences and history.
- **Startup:** the library appears straight from IndexedDB; the folder database and encrypted store are reconciled in the background and changes made meanwhile win. If the selected Android folder is missing, ScreenMark asks you to choose a folder again.
- **Metadata refresh:** when online metadata is enabled, the app checks titles with a saved provider and ID on startup and resume. The configured daily, weekly or monthly interval decides which saved details need refreshing; `never` disables automatic refresh. Requests run only while the app is visible and online, use the configured one-to-three workers, and failed automatic requests back off for six hours. A restored queued entry whose title no longer has an enabled, usable source is marked skipped instead of being retried indefinitely. Manual refresh and retry remain available.
- **Images:** **Settings → Metadata & Storage → Image storage** controls folder copies: save all images, save title covers and backdrops, or keep images online only. Poster grids, watchlists and detail heroes use native lazy loading and asynchronous image decoding. When a title has a saved thumbnail path, the UI looks up its IndexedDB Blob as the image nears the viewport; a poster placeholder remains visible until the image loads and returns if loading fails. Episode stills and other provider images keep their own URLs. Saved-folder images can restore the IndexedDB cache after a cache clear, and Android removes cache entries for deleted titles during its background cache-fill pass.
- **Export and backups:** Settings → Backups streams the library in chunks to a JSON file. It includes notes, saved metadata, and artwork; restore merges titles into the current library. Daily folder TAR backups include the portable database and saved image files. Restore accepts the archive's root database file or the mirrored `database.json` inside the folder tree. TAR paths use PAX support through Apache Commons Compress, and file contents stream from Android's Storage Access Framework instead of being buffered into a second full in-memory copy. The optional Android `.sqdb` background backup contains the current encrypted per-title records and metadata and can be imported on the same installation; use JSON to move a library between devices.
- **Android:** the app bridge uses the `EncryptedStore` Capacitor plugin to save library items and metadata. The local storage value is maintained as a browser-compatible mirror. Notes are kept in IndexedDB, encrypted item records, folder snapshots, and exports.
- **Metadata cache:** responses use the Cache Storage namespace `splitapp_screenmark_metadata`; API-key-bearing requests are not cached.
- **Secrets:** API keys are stored in this app's preferences. Do not commit personal API keys or `.env` files.

Opening a title's details (or refreshing metadata) saves the provider response in `cachedDetails` and a compact `facts` summary on the item. The portable folder tree stores movies at `<app-key>-db/movies/<metadata-source>/<item-id>/` and series at `<app-key>-db/series/<metadata-source>/<item-id>/`. The source folder uses the provider key (such as `tmdb` or `tvmaze`), or `manual` for entries without a metadata source. Each title folder contains an `index.json` and any saved images, keeping entries from different providers separate. Existing `shows/`, direct category folders, and `titles/` folders are recognized during startup sync and migrated after the new copy is safely written. The root database JSON and TAR backup remain complete portable snapshots.

The three apps use separate storage keys and separate cache names.
