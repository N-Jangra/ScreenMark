# ScreenMark storage

## Portable storage and durability

IndexedDB is WebView origin storage, not a file in `/sdcard/Android/data`. On Android it is stored inside the app's private WebView profile, under `app_webview/Default/IndexedDB/https_localhost_0.indexeddb.leveldb` (plus a sibling `.blob` directory for large values). For the installed debug test package, ADB can inspect it with `adb shell run-as com.cuemark.screenmark.test ls app_webview/Default/IndexedDB`; production uses `com.cuemark.screenmark` instead of the `.test` suffix. This is a LevelDB database, not one portable SQLite/JSON file, and the app should access it through IndexedDB. Startup makes a best-effort request for Chromium persistent-storage status; the tested Android WebView returned `false` from `navigator.storage.persisted()`, so this request does not guarantee protection from storage pressure. In addition to the internal Keystore-backed records, Android now keeps an encrypted per-title recovery mirror under `/sdcard/Android/data/<package>/files/CueMark/ScreenMark/` (`records/*.enc`, `meta.enc`, and any legacy `state.enc`). The first full startup backfills every library record from IndexedDB in small background batches; later title changes/deletions update individual files atomically. If IndexedDB and the internal record store are empty, the app can recover titles and metadata from this mirror. Inspect the test mirror with `adb shell ls -la /sdcard/Android/data/com.cuemark.screenmark.test/files/CueMark/ScreenMark`. App-specific storage survives cache clearing, but Android removes it when app data is cleared or the app is uninstalled. The selected Storage Access Framework folder is the user-visible portable database/artwork mirror; artwork blobs remain in IndexedDB and/or that selected folder. Export a `.json.gz` backup or password-protected `.sqx` transfer file for device migration/recovery. `.sqx` derives an AES-256-GCM key with PBKDF2-SHA-256 (310,000 iterations) and authenticates chunks independently; keep the password.

An `.sqx` transfer contains every library title with its source links and saved details, preferences, history, and artwork found in the IndexedDB image stores or selected folder. This includes cached galleries and episode stills that never reached the selected folder. Images not yet cached or mirrored cannot be embedded without downloading them. Imports remap the embedded image paths and restore preferences and activity history; sender folder URIs are discarded because SAF grants are device-local. Save `.sqx` through Android's Save As picker, share it directly from ScreenMark, or send it from a file manager to another device and import it from Settings → Backups. Android shows an export progress/completion notification when notifications are allowed.

- **Library:** titles live in IndexedDB (`screenmark_library`: `items`, `meta`, `details`, `images` and `thumbs` stores) and are written per changed title by a data worker. Full provider details are held separately from list records; `images` indexes artwork URLs and `thumbs` holds cached image blobs. The `items` store uses its ID key for normal edits and a compound `metadataSource` / `category` / `providerId` index for direct provider-link lookups. Schema version 6 adds the provider-link index, version 7 adds the artwork catalog, and version 8 adds the separate full-detail store. Unused indexes and the obsolete share/PDF cache were removed in earlier upgrades. If the data worker stops or times out, queued operations are replayed in order by the main-thread fallback after its change-detection cache is reloaded. `localStorage` (`splitapp_screenmark_v1`) keeps only a small startup mirror of preferences and history.
- **Startup:** the library appears straight from IndexedDB; the folder database and encrypted store are reconciled in the background and changes made meanwhile win. If the selected Android folder is missing, ScreenMark asks you to choose a folder again.
- **Metadata refresh:** when online metadata is enabled, the app checks titles with a saved provider and ID on startup and resume. The configured daily, weekly or monthly interval decides which saved details need refreshing; `never` disables automatic refresh. Requests run only while the app is visible and online, use the configured one-to-three workers, and failed automatic requests back off for six hours. A restored queued entry whose title no longer has an enabled, usable source is marked skipped instead of being retried indefinitely. Manual refresh and retry remain available.
- **Images:** **Settings → Metadata & Storage → Image storage** controls saved image copies: save all images, save title covers and backdrops, or keep images online only. With **Save all images**, Android stores posters, portrait covers, backdrops, screenshots, poster galleries and episode stills as image blobs in IndexedDB. Collection and watchlist images, detail galleries, profile covers and episode pages look up those blobs before using online URLs. A background startup pass fills missing images for older saved titles; new titles cache their artwork as part of the resumable detail sync. The selected folder can also hold a portable copy of saved artwork. In browsers, image URLs still use normal HTTP loading, while full detail pages can restore artwork blobs from IndexedDB. If a metadata source has no still for an episode, ScreenMark tries to match the series to one exact TVmaze title/year result and fills only episodes with matching season and episode numbers. A series poster or backdrop is never stored as an episode still. Newly added titles appear on **Sync status** during detail and image sync; the compact overlay shows the active title and episode/season counts. Failed image downloads and writes remain retryable. **Posters and covers only** and **Online only** do not download episode stills. **Clear all temporary cache** removes WebView and response caches but preserves saved artwork in IndexedDB; **Clear image cache** removes those persistent image blobs. Deleted-title blobs are pruned on Android startup.
- **Export and backups:** Settings → Backups streams the library in chunks to a JSON file or password-protected `.sqx` file. Transfers embed cached artwork from IndexedDB and selected-folder files, notes, saved metadata, preferences and activity history; restore merges titles into the current library. Images not already cached/mirrored are omitted. The Android share action streams the encrypted transfer into a temporary share file in bounded chunks before opening the system chooser. Daily folder TAR backups include the portable database and saved image files. Restore accepts the archive's root database file or the mirrored `database.json` inside the folder tree. TAR paths use PAX support through Apache Commons Compress, and file contents stream from Android's Storage Access Framework instead of being buffered into a second full in-memory copy. The optional Android `.sqdb` background backup contains the current encrypted per-title records and metadata and can be imported on the same installation.
- **Android:** the app bridge uses the `EncryptedStore` Capacitor plugin to save library items and metadata. The local storage value is maintained as a browser-compatible mirror. Each encrypted native item/meta record is atomically mirrored into app-specific external files and can recover an empty IndexedDB/internal record store. Notes are kept in IndexedDB, encrypted item records, folder snapshots, and exports. A chosen backup folder is usable only when Android grants and persists both read and write access; the app validates the picker result before saving it.
- **Metadata cache:** responses use the Cache Storage namespace `splitapp_screenmark_metadata`; API-key-bearing requests are not cached.
- **Secrets:** API keys are stored in this app's preferences. Do not commit personal API keys or `.env` files.

Opening a title's details (or refreshing metadata) saves the provider response in `cachedDetails` and a compact `facts` summary on the item. The portable folder tree stores movies at `<app-key>-db/movies/<metadata-source>/<item-id>/` and series at `<app-key>-db/series/<metadata-source>/<item-id>/`. The source folder uses the provider key (such as `tmdb` or `tvmaze`), or `manual` for entries without a metadata source. Each title folder contains an `index.json` and any saved images, keeping entries from different providers separate. Existing `shows/`, direct category folders, and `titles/` folders are recognized during startup sync and migrated after the new copy is safely written. The root database JSON and TAR backup remain complete portable snapshots.

The three apps use separate storage keys and separate cache names.

## Backups and restore (0.1.5)

Backup JSON never contains temporary `blob:` image links (they are dropped on export), and the browser export reads each title's full details first. Backup JSON is `version: 2` (top-level `index`, a `backupRef` per title with source, source id, category, title and year). Exports are gzip-compressed (`.json.gz`) in the browser and in the Android app; the Android app also offers `.sqx`, which encrypts the compressed stream in authenticated chunks using a PBKDF2-derived AES-256-GCM key. On Android, **Encrypted transfer file → Create** opens Save As; **Share encrypted transfer → Share** stages bounded chunks and opens Android's share chooser without a location picker. Artwork reads use small, low-memory-aware parallel groups, and the native chooser grants its FileProvider URI through `ClipData`. Restore detects the format by content, matches existing titles by source + source id then by title and year, rebuilds the metadata link from `backupRef`, restores included image paths, preferences and activity history, and queues titles for sync. CSV exports include `Source`, `SourceID`, `ID`, dates and tracking fields; TXT is `Title (Year)`.
